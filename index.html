ไม่ใช่

  • ไม่ใช่ระบบของร้าน/โรงเรียน/คลินิก (Business SaaS อยู่นอกขอบเขต) · ระบบครู/เทรนเนอร์แยกไปเป็นอีกโปรเจกต์แล้ว
  • ไม่รับ ไม่ถือ ไม่โอนเงินหรือเครดิตแทนร้าน ยอดในแอปเป็น บันทึกส่วนตัวที่ผู้ใช้กรอกเอง
  • ไม่ใช้ AI คำนวณยอด ไม่ใช้ NAS ไม่แชร์คอร์สหรือส่งข้อความหาคนอื่น

หลักการแกน 5 ข้อ

  1. Ledger แบบเพิ่มอย่างเดียว (append-only) ทุกการตัดยอดเป็นรายการถาวร แก้ผิดด้วยรายการหักล้าง (แก้รายการ) ประวัติเดิมยังอยู่ ขึ้นป้าย "แก้แล้ว"
  2. ยืนยันด้วยตัวเองทุกครั้ง ต้องเห็นยอดก่อนและหลังแล้วกดยืนยัน กันกดซ้ำด้วย idempotency key
  3. ไม่มีการตัดอัตโนมัติ ถึงเวลาเรียนแล้วไม่กดตอบก็ไม่ตัด กด "ลา" หรือ "งดสอน" ก็ไม่ตัด
  4. ตอบในแชทก่อน (reply-first) การกดในเมนูใช้ postback แล้วตอบกลับด้วย reply ส่วน push (ข้อความที่ระบบส่งเอง) ใช้เฉพาะแผนที่มีโควตา
  5. ยอดจริงมาจากฐานข้อมูลเท่านั้น หน้าจอและข้อความเก่าในแชทไม่ใช่แหล่งความจริง ทุกการกดโหลดสถานะล่าสุดใหม่ เงินเก็บเป็นสตางค์ เวลาเก็บเป็นนาที

นับเป็นมูลค่าบริการ (VALUE)

เช่น จ่ายร้านทำผม 50,000 บาท ร้านให้มูลค่าบริการ 70,000 บาท

เก็บเป็นสตางค์จำนวนเต็ม · แสดง "เงินที่คุณจ่ายร้าน" กับ "ส่วนที่ร้านให้เพิ่ม" แยกกัน

ตัวอย่าง: มูลค่า 70,000 (ร้านให้เพิ่ม 20,000) ใช้บริการ 3,500 → คงเหลือตามที่คุณบันทึก 66,500 บาท

คอร์สแบบมูลค่าเป็น บันทึกส่วนตัวที่ผู้ใช้กรอกเอง เราไม่ได้รับ ถือ หรือโอนเงินหรือเครดิตใดๆ ทุกจุดที่แสดงยอดแบบนี้ต้องใช้คำ "ตามที่คุณบันทึก" และแสดงข้อความชี้แจงสั้นแบบเต็มทุกคำ (ห้ามย่อหรือซ่อน) ตามเงื่อนไขของ law เพื่อไม่ให้ดูเหมือนกระเป๋าเงินหรือ e-money

ข้อมูลของคอร์ส

ชื่อคอร์ส · ชนิด · ป้ายชื่อ (ใช้กับใคร · ไม่บังคับ) · ร้าน/ครู (ไม่บังคับ) · ยอดตั้งต้น · ยอดคงเหลือ · เงินที่จ่ายร้าน (เฉพาะ VALUE · ไม่บังคับ) · วันที่ซื้อ · วันหมดอายุ (ไม่บังคับ) · หมายเหตุ · สถานะใช้อยู่/เก็บเข้าคลัง · เวลาไทย (Asia/Bangkok)

ชื่อคอร์สยาว 1–60 ตัว · ป้ายชื่อ 1–40 ตัว · ฟอร์มเตือนไม่ให้ใส่ข้อมูลสุขภาพ (เช่น ชื่อโรคหรือการบำบัด) เพราะชื่อคอร์สจะขึ้นบนหน้าจอล็อกมือถือตอนมีข้อความเตือน

กฎการตัดยอด

  • ทุกการตัดเป็น database transaction ที่ล็อกคอร์ส ตรวจยอดคงเหลือ และใช้ idempotency key กดซ้ำหรือกดพร้อมกันสองเครื่อง = ตัดครั้งเดียว ("รายการนี้ตัดยอดไปแล้ว ไม่ได้ตัดซ้ำ")
  • ยอดไม่ติดลบ ถ้ายอดไม่พอ ระบบไม่ตัดและบอกทางแก้ (ลดจำนวน หรือ บันทึกซื้อเพิ่ม)
  • คอร์สเก่าจาก v2 ที่ยอดติดลบอยู่แล้ว (ใช้เกินที่เติมไว้) ยังไม่ให้ตัดเพิ่ม จนกว่าจะบันทึกซื้อเพิ่มให้ยอดพอ
  • ห้ามให้ LLM คำนวณหรือเขียนยอด · ห้ามเชื่อตัวเลขที่ส่งมาจากเครื่องผู้ใช้ ยอดก่อนและหลังคำนวณที่เซิร์ฟเวอร์
  • บันทึกซื้อเพิ่ม = บวกยอดเข้าคอร์สเดิม (ซื้อแพ็กเดิมเพิ่มกับร้าน) แสดงยอดก่อน → หลังก่อนยืนยัน

วันหมดอายุ

  • ไม่บังคับ · แก้ทีหลังได้เมื่อร้านขยายเวลา · ตั้งเป็นวันที่ผ่านไปแล้วไม่ได้ (วันนี้ได้)
  • คำนวณ "อีกกี่วัน" จากวันที่ฝั่งเซิร์ฟเวอร์ตามเวลาไทย ไม่ใช่นาฬิกาเครื่อง
  • สถานะ 5 แบบ: ยังไม่หมดอายุ · อีก N วัน (≤ 14) · หมดอายุวันนี้ (ยังตัดได้ถึงสิ้นวัน) · หมดอายุแล้ว · ไม่มีวันหมดอายุ
  • หมดอายุแล้ว = ยังตัดไม่ได้ ต้องแก้วันหมดอายุก่อนถ้าร้านขยายให้
  • ตอนนี้ฐานข้อมูลมีช่องวันหมดอายุแล้ว แต่ หน้าจอยังไม่ได้ทำ (P5c-1)

เก็บเข้าคลัง (archive)

  • คอร์สที่ใช้หมดหรือเลิกใช้ เก็บเข้าคลังได้ ประวัติยังอยู่ และ ไม่นับในโควตาคอร์สที่ใช้อยู่
  • นำกลับมาใช้ได้จากแท็บ "คลัง" ถ้าโควตาแผนยังว่าง ถ้าเต็มต้องเก็บคอร์สอื่นก่อน
  • ปุ่มในข้อความเก่าที่ชี้ไปคอร์สในคลัง = "คอร์สนี้เก็บเข้าคลังไปแล้ว ไม่ได้ตัดยอด"
  • หน้าจอคลังยังไม่มี (อยู่ในงานหน้าแรก/Flow C)

แก้รายการ (reversal)

  • ไม่มีการลบหรือแก้ทับ · "แก้รายการ" = เพิ่มรายการใหม่หักล้างรายการเดิม พร้อมเหตุผล (บังคับ) และ audit log
  • รายการเดิมยังอยู่ในประวัติ ขึ้นป้าย "แก้แล้ว" · แก้ซ้ำไม่ได้ · ถ้าแก้แล้วยอดจะติดลบ ระบบไม่ให้แก้
  • แก้รายการเข้าเรียนของคลาส → คลาสนั้นกลับไปอยู่ใน "รายการรอยืนยัน" เลือกใหม่ได้

สถานะคลาสตามตาราง (Flow B)

  • เข้าเรียน → ตัดตามระยะเวลา/จำนวนของคลาส (VALUE ให้กรอกมูลค่าก่อน)
  • ลา / งดสอน → บันทึกสถานะ ไม่ตัดยอด
  • ไม่กด → ค้างเป็น "รอยืนยัน" ไม่ตัด ไม่เตือนซ้ำ กลับมากดข้อความเก่าหรือเข้าหน้ารอยืนยันทีหลังได้ (แม้ผ่านไป 30 วันก็ยังอ้างคลาสเดิม)
  • 1 คลาสในตาราง = push ได้ไม่เกิน 1 ครั้ง แม้มี retry

4.1 สมัครและเข้าใช้ด้วย LINE

  1. ผู้ใช้เจอหน้า landing สาธารณะ หรือเพิ่มเพื่อน LINE OA ตัดคอร์ส แล้วเห็น rich menu
  2. กด เริ่มใช้ฟรีด้วย LINE หรือปุ่มเมนูใดก็ได้ → เปิด LIFF ภายใน LINE → login ด้วย LINE อัตโนมัติ (ไม่มีรหัสผ่าน ไม่มียืนยันอีเมล)
  3. หน้าสมัครให้ติ๊กช่องรับรอง (ห้ามติ๊กไว้ก่อน · ปุ่มไปต่อใช้ไม่ได้จนกว่าจะติ๊ก):
    "ฉันอายุ 20 ปีขึ้นไป หรือผู้ปกครองของฉันได้อ่าน[ข้อกำหนดการใช้งาน]และ[ประกาศความเป็นส่วนตัว]แล้ว และยินยอมให้ฉันใช้บริการตามข้อกำหนดการใช้งาน"
  4. เก็บเฉพาะ: ติ๊กหรือไม่ + เวลา + เวอร์ชันเอกสารทั้งสอง · ไม่เก็บอายุหรือวันเกิด
  5. เสร็จ = บัญชีแผน Free · ช่องเดียวกันนี้ใช้อีกครั้งตอน ชำระเงินครั้งแรก และตอน เอกสารเปลี่ยนเวอร์ชัน (หน้า "ข้อกำหนดและประกาศความเป็นส่วนตัวมีการอัปเดต" → ปุ่ม "ยอมรับและใช้งานต่อ")

ถ้ายังไม่สมัครแต่กด "ตัดคอร์ส" ในแชท → บอทตอบ "คุณยังไม่ได้สมัครใช้งาน · เปิดแอปเพื่อสมัครด้วย LINE ก่อน แล้วค่อยกลับมาตัดคอร์ส" พร้อมปุ่ม เปิดแอป (ถ้าสมัครแล้วแต่ยังไม่มีคอร์ส ใช้ข้อความ "ยังไม่มีคอร์ส · เพิ่มคอร์สแรกได้เลย" แทน)

หน้า landing สาธารณะ (ข้อความใหม่ · ต้องผ่าน law ก่อนใช้)

law ตรวจแล้วว่าหน้า landing เดิมใน trunk ไม่ตรงความจริงภายใต้ v3 (พูดถึงทดลองใช้ ครอบครัว เตือนผู้ใช้ Free) จึงเขียนใหม่ทั้งหน้า ลำดับ: hero → ปุ่มเริ่ม → จุดเด่น 4 ข้อ → 3 ขั้น → ราคา

  • หัว: "ดูยอดคงเหลือคอร์สที่ซื้อไว้ล่วงหน้า ในที่เดียว"
  • รอง: "ใช้ได้กับเรียนพิเศษ นวด ทำผม ล้างรถ แล้วตัดยอดเองทุกครั้งที่ใช้บริการ"
  • ป้าย: "ใช้ฟรีไม่จำกัดเวลาด้วยแผน Free"
  • 3 ขั้น: กดปุ่ม เริ่มใช้ฟรีด้วย LINE แล้วยืนยันการสมัคร → เพิ่มคอร์สที่ซื้อไว้ ใส่จำนวนที่เหลือ และวันหมดอายุถ้ามี → ใช้บริการแล้วกดตัดคอร์สเอง ดูยอดก่อนและหลังตัด แล้วกดยืนยัน
  • จุดเด่น: ยอดเปลี่ยนเมื่อคุณกดเองเท่านั้น · เตือนก่อนคอร์สหมดอายุ · รู้ยอดคงเหลือ และประวัติไม่หาย · ใช้ได้กับคอร์สหลายแบบ
  • เงื่อนไขปล่อย: ขั้น "เพิ่มคอร์ส" ปล่อยได้เมื่อ P5c-1 และ Flow C ใช้งานจริงแล้ว · บล็อกราคาห้ามแสดงจนกว่าจะมีราคา v3 ในระบบและเปิดรับชำระ
  • ตั้งใจไม่อ้าง: ครอบครัว/ลูก/คลาส · "ไม่ต้องจดเอง" · ทดลองใช้ฟรี · เตือนก่อนคลาสกับผู้ใช้ Free · ใช้ร่วมกัน · ตัดอัตโนมัติ · สิ่งที่เกิดเมื่อแผนเสียเงินหมดอายุ (ยังไม่ตัดสิน)

4.3 Flow A — ตัดคอร์สในแชท รีวิวผ่าน รอรวม

  1. กด ตัดคอร์ส → เซิร์ฟเวอร์ตรวจลายเซ็น LINE และสิทธิ์ (ต้องเป็นเจ้าของบัญชี) → ตอบ Flex carousel "เลือกคอร์สที่จะตัด" แสดงคอร์สที่ใช้อยู่พร้อมยอด
  2. คอร์สเยอะ: 1 carousel ได้ 12 ใบ = 11 คอร์ส + ใบ "ดูเพิ่ม · ยังมีอีก N คอร์ส" (หน้าถัดไป) และปุ่ม "ดูทั้งหมดในแอป"
  3. กด "เลือกคอร์สนี้" → ถามจำนวน: แบบครั้ง "ใช้กี่ครั้ง?" (1 ครั้ง · 2 ครั้ง · จำนวนอื่น) · แบบชั่วโมง "ใช้กี่ชั่วโมง?" (1 · 1.5 · 2 ชม. · จำนวนอื่น) ตัวเลือกที่ตรงตารางเรียนต่อท้าย "· ตามตาราง"
  4. หน้า ยืนยันการตัดคอร์ส: ชื่อคอร์ส · ใช้เท่าไร · ก่อนตัด → หลังตัด (จากเซิร์ฟเวอร์) · ปุ่ม "ยืนยันตัด" / "ยกเลิก"
  5. ยืนยัน → ตัดยอดใน transaction เดียว → ตอบ "ตัดยอดแล้ว" (แสดงหลังฐานข้อมูลตอบสำเร็จเท่านั้น) + คงเหลือ + ปุ่ม "ดูประวัติ" / "ตัดคอร์สอื่น"
  6. กด "ยกเลิก" → "ยกเลิกแล้ว ยังไม่ได้ตัดยอด" · กดยืนยันซ้ำ → "รายการนี้ตัดยอดไปแล้ว ไม่ได้ตัดซ้ำ"
