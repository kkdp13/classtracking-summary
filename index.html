02เส้นทางโปรเจกต์

ทำแล้วเรียนรู้ เปลี่ยนทิศเมื่อข้อมูลจริงบอกว่าทางเดิมใช้ไม่ได้

23 ส.ค. — เริ่มโปรเจกต์ (v1)ต้นแบบเก็บข้อมูลในเครื่อง → schema Postgres แบบ append-only + hash chain · ทดสอบเจาะ RLS 21 ข้อผ่าน · ขึ้น VPS ของเราเอง
ก.ย. — v1 ออนไลน์เว็บแอป + ระบบบัญชีอีเมล/รหัสผ่าน · รองรับลูกหลายคน · ย้ายข้อมูลจากเครื่องขึ้นฐานข้อมูล
11 ก.ย. — audit จาก log จริงมี 8 บัญชี ยืนยันอีเมลได้ 2 · คลาส 0 รายการ ⇒ ไม่มีใครใช้จริง เพราะประตูเข้าแอปยากเกินไป (รหัสผ่าน · ยืนยันอีเมล · session หลุดบน iOS) และระบบไม่เคยเตือนวันเรียน
29 ต.ค. — ตัดสินใจสร้าง v2 บน LINENext.js + LIFF + LINE OA · login ด้วย LINE ครั้งเดียว · เตือนผ่านแชทพร้อมปุ่ม · สร้าง M0–M7 จบในวันเดียวกันและย้ายระบบขึ้นจริงคืนนั้น
30 ต.ค. – 1 พ.ย. — ขัดเกลาและทำ opsเตือนก่อนเรียน 60 นาที · กฎเปลี่ยนวันเรียน · backup นอก VPS (restic → Backblaze B2) · health alert ผ่าน Telegram และ healthchecks.io
1–2 พ.ย. — PDPA และแผนเปิดตัวกลไกลบข้อมูลทั้งครัวเรือน · backup ที่รู้ว่าข้อมูลไหนถูกลบ · ร่างประกาศความเป็นส่วนตัว · แผนเปิดตัว · แยกระบบครู/เทรนเนอร์ออกเป็นอีกโปรเจกต์

03Scope — ทำอะไร ไม่ทำอะไร

อยู่ใน scope (v2)

  • ผู้ใช้คือ ผู้ปกครอง ใช้เป็นครัวเรือน (2 คนดูข้อมูลชุดเดียวกัน)
  • จัดการลูก · คลาส · วันและเวลาเรียน · ชั่วโมงต่อครั้ง · นโยบายลา (ลาแล้วตัดชั่วโมงหรือไม่ตัด)
  • เติมชั่วโมง (topup) · บันทึกเข้าเรียน / ลา / งดสอน / ขาด / ปรับยอด
  • เตือนผ่าน LINE ก่อนเรียน พร้อมปุ่มตอบในแชท
  • ดูยอดคงเหลือและประวัติในแอป LIFF
  • สมุดบัญชีแก้ย้อนหลังไม่ได้ แก้ผิดด้วยรายการกลับรายการ (reversal)
  • backup · health alert · กลไกลบข้อมูลตาม PDPA

นอก scope (ตอนนี้)

  • ฟีเจอร์ฝั่งโรงเรียน / ครู / เทรนเนอร์ (แยกไปเป็นโปรเจกต์ใหม่ คนละ LINE OA ไม่ผสมข้อมูล)
  • รับชำระเงิน · แพ็กเกจเสียเงิน
  • เปิดสมัครสาธารณะแบบ self-serve
  • PWA · MINI App · ภาษาอังกฤษ
  • จำกัดจำนวนคลาสแบบทดลอง (ประเมินแล้วว่าไม่ควรทำ)
ข้อขัดกันที่ต้องตัดสิน: แผนเดิมกำหนดให้ v2 ใช้ในครอบครัวเท่านั้น แต่เป้าหมายล่าสุดคือ "ขายให้ได้มากที่สุด" ต้องปรับ scope ข้อนี้ก่อนเปิดให้คนนอก

06ข้อดี (Pro) และข้อเสีย (Con)

Pro

  • ข้อมูลเชื่อถือได้: สมุดบัญชี append-only 3 ชั้น (trigger ห้ามแก้/ลบ · role แอปเขียนเพิ่มได้อย่างเดียว · hash chain)
  • ใช้งานจริงแล้ว: ยอดหลังย้ายระบบตรงกับระบบเก่าทุกคลาส · เตือนจริงทำงานตั้งแต่ 31 ต.ค.
  • ทนต่อการกดซ้ำและ LINE ส่งซ้ำ: dedupe ทั้งระดับ event และระดับคาบ
  • ผ่านการตรวจหลายชั้น: ทุกก้อนโค้ดผ่านผู้รีวิว และผ่าน audit อิสระก่อน deploy
  • ops ครบ: backup รายวันพร้อมนับแถว · สำรองนอกเครื่อง · แจ้งเตือนเมื่อระบบล่ม · คู่มือ rollback
  • เตรียม PDPA ไว้แล้ว: กลไกลบทั้งครัวเรือน · backup ที่ลบตามได้ภายใน 90 วัน · ร่างประกาศผ่านการตรวจแล้ว
  • ย้ายง่าย: ทุกไฟล์อยู่ในโฟลเดอร์เดียว deploy บนเครื่องของเราเอง ไม่ผูกกับผู้ให้บริการรายใด

Con

  • ยังไม่เคยพิสูจน์ตลาด: ยังไม่ได้คุยกับผู้ปกครองหรือโรงเรียนอื่นสักราย
  • ผูกกับ LINE: โควตาหมด = ระบบเงียบทั้งระบบ · เกิน 300 ข้อความต้องจ่าย 1,280 บาท+VAT/เดือน (ประมาณ 3–4 ครัวเรือนก็ชนเพดาน)
  • รับคนนอกได้ยาก: ช่องทาง login ยังอยู่โหมด Developing ต้องเพิ่ม Tester และ allowlist ด้วยมือทีละครัวเรือน
  • ยังไม่ผ่านเกณฑ์ "เสร็จ" ของตัวเอง: ต้องใช้ผ่าน LINE ต่อเนื่อง 2 สัปดาห์ · probe บางข้อยังไม่ได้ทดสอบ (Android · คนนอก allowlist · กดระหว่างแอป restart)
  • แยกข้อมูลหลายครัวเรือนด้วยเทสต์ ไม่ใช่ด้วย DB: พอสำหรับ 5 ครัวเรือน ไม่พอสำหรับเปิดสาธารณะ
  • PDPA ยังไม่จบ: ประกาศจริงรอชื่อแอป อีเมลกลาง และคำตอบทนาย (รวมเรื่อง backup ของผู้ให้บริการที่เก็บในต่างประเทศ)
  • ซับซ้อนกว่าขนาดผู้ใช้: stack และขั้นตอน deploy หนักสำหรับครอบครัวเดียว ภาระดูแลตกที่คนเดียว
  • ยังไม่มีชื่อแบรนด์: ชื่อที่ชอบชนกับแอปอื่น ใช้ชื่อชั่วคราว "สมุดชั่วโมงเรียน" ไปก่อน

07เทคนิคโดยสรุป

Stack
  • Next.js 16 · TypeScript strict · Tailwind 4
  • PostgreSQL 16 · drizzle (migration 13 ชุด)
  • worker แยก: scheduler ทุก 60 วิ + outbox ส่งข้อความ
  • LINE Login (LIFF) + LINE Messaging API (webhook / postback)
  • Docker compose บน VPS ของเราเอง ผ่าน Cloudflare tunnel
ความปลอดภัยและความถูกต้อง
  • ตรวจลายเซ็น webhook แบบ timing-safe · จำกัดขนาด body · rate limit
  • session cookie แบบ __Host- · CSRF · env ขาดแล้วไม่ยอมรัน (fail-closed)
  • เทสต์ mutant: ถอดกลไกกันแก้ทีละชั้นแล้วเทสต์ต้องแดง
  • เทสต์แยกข้อมูลครัวเรือนครอบคลุมทุก export
  • เก็บ secret นอก repo และนอก build context

วิธีทำงานของทีม

วางแผน / แตกงาน→ เขียนโค้ด→ รีวิว (four-eyes)→ audit อิสระ→ เจ้าของอนุมัติ deploy→ ตรวจหลัง deploy ตามคู่มือ

08ความเสี่ยงที่ต้องจับตา

ความเสี่ยงระดับทางรับมือ
รับข้อมูลลูกของครอบครัวอื่นก่อน PDPA จบสูงห้ามรับคนนอกจนกลไกลบ + ประกาศจริงพร้อม
โควตา LINE หมด ระบบเงียบสูงเตือนที่ 80% · รวมคลาสวันเดียวเป็นข้อความเดียว · หรือจ่ายแพ็ก Basic
เปิด login สาธารณะแล้วย้อนกลับไม่ได้กลางคงโหมด Developing + Tester ในช่วงทดลอง
เตือนตกหล่นครั้งเดียว ความไว้ใจหายกลางhealth alert ภายนอก · ดู outbox ที่ส่งไม่ผ่าน
สร้างของที่ไม่มีใครต้องการกลางคุยผู้ปกครอง 8–10 คนก่อนเขียนโค้ดเพิ่ม
